3. ADDITIONAL WHITE-BOX TESTING

Three additional tests were implemented in tests/test_whitebox.py.

WB-01: test_dues_blocked_above_1000
Target: The true outcome of the outstanding-dues decision
in registration_decision().

WB-02: test_waitlisted_student_added_once
Target: The WAITLISTED handling branch in register_course(),
where a student not already on the waitlist is appended.

WB-03: test_waitlisted_student_not_added_twice
Target: The duplicate-entry condition in register_course(),
where an existing waitlist entry must not be added again.

All three additional white-box tests passed.

Important limitation:
The two waitlist-handling tests use monkeypatch to simulate
a WAITLISTED result from registration_decision(). This allows
the waitlist-handling branches in register_course() to be
tested even though the current implementation cannot naturally
produce WAITLISTED through valid registration_decision() inputs.

6. REMAINING COVERAGE GAP

The WAITLISTED return statement at line 54 remains uncovered.

The current implementation validates that enrollment is
between zero and course capacity before reaching the
waitlist decision.

However, the later waitlist condition checks whether
enrollment is greater than capacity.

This condition cannot be true after the earlier validation
has succeeded.

Consequently, this return statement is unreachable through
normal valid execution with the current implementation.

The remaining partially covered branch is associated with
this unreachable decision outcome.

7. FUNCTIONAL TEST FAILURES

Fifteen black-box tests remained failed in the combined run.

The failures revealed implementation defects involving:

- Credit-limit boundary handling.
- Prerequisite validation.
- Outstanding-dues handling.
- Full-course waitlisting.
- Registration decision priority.
- Course withdrawal updates.

These failures were preserved as evidence. The original
registration.py implementation was not modified during
the initial coverage measurement and white-box testing phase.

8. CONCLUSION

White-box testing was performed using control-flow analysis,
basis path analysis, condition analysis, and additional
targeted pytest tests.

Initial statement coverage was 94.74%, and initial branch
coverage was 88.46%.

After adding three white-box tests, statement coverage
increased to 98.25%, and branch coverage increased to 96.15%.

The combined test suite contained 61 tests, of which
46 passed and 15 failed.

The results demonstrate that additional structural tests
improved coverage. However, high coverage does not guarantee
functional correctness.

The remaining uncovered WAITLISTED return statement and
the outstanding functional failures were documented rather
than hidden or artificially corrected.

The original source code and legitimate test failures were
preserved for subsequent defect investigation.
